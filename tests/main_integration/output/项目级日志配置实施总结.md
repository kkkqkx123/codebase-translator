### 2. 实现配置合并逻辑 ✓

**文件**: `src/config/loader.rs`

**修改内容**:
```rust
pub fn load(&self) -> Result<(GlobalConfig, ProjectConfig)> {
    let mut global = self.load_global()?;
    let project = self.load_project()?;

    // Merge logging configuration: project config overrides global config
    if let Some(ref project_logging) = project.logging {
        global.logging = project_logging.clone();
    }

    // Apply environment variable overrides (highest priority)
    global.apply_env_vars();

    Ok((global, project))
}
```

**配置优先级**:
1. 环境变量（最高）
2. ProjectConfig.logging
3. GlobalConfig.logging
4. 默认值（最低）

### 3. 添加环境变量支持 ✓

**文件**: `src/config/global.rs`

**修改内容**:
```rust
pub fn apply_env_vars(&mut self) {
    // ... 现有的环境变量处理 ...
    
    // Logging configuration environment variables
    if let Ok(log_level) = std::env::var("TRANSLATOR_LOG_LEVEL") {
        self.logging.level = log_level;
    }
    if let Ok(log_output) = std::env::var("TRANSLATOR_LOG_OUTPUT") {
        self.logging.output = log_output;
    }
    if let Ok(log_format) = std::env::var("TRANSLATOR_LOG_FORMAT") {
        self.logging.format = log_format;
    }
    if let Ok(log_file) = std::env::var("TRANSLATOR_LOG_FILE") {
        self.logging.file = Some(log_file);
    }
}
```

**支持的环境变量**:
- `TRANSLATOR_LOG_LEVEL`: 覆盖日志级别
- `TRANSLATOR_LOG_OUTPUT`: 覆盖输出目标
- `TRANSLATOR_LOG_FORMAT`: 覆盖日志格式
- `TRANSLATOR_LOG_FILE`: 覆盖日志文件路径

## 使用示例

```toml
# .translator
[translate]
source_langs = ["AUTO"]
target_lang = "EN"

[logging]
level = "debug"
output = "file"
format = "json"
file = "logs/translator.log"
```

```yaml
# GitHub Actions
- name: Run translation
  env:
    TRANSLATOR_LOG_LEVEL: debug
    TRANSLATOR_LOG_OUTPUT: stdout
    TRANSLATOR_LOG_FORMAT: json
  run: |
    cargo run --release

translation:

```

## CI/CD场景适配

### 场景1：多项目CI/CD

**需求**: 不同项目需要不同的日志级别

**解决方案**: 每个项目有自己的`.translator`配置文件

```toml
# 项目A/.translator
[logging]
level = "debug"  # 详细日志用于调试
```

```toml
# 项目B/.translator
[logging]
level = "info"   # 正常日志级别
```

### 场景2：CI环境日志收集

**需求**: CI环境需要将日志输出到stdout，本地开发环境输出到文件

**解决方案**: 使用环境变量覆盖

```yaml
# CI环境
- name: Run translation in CI
  env:
    TRANSLATOR_LOG_OUTPUT: stdout
    TRANSLATOR_LOG_FORMAT: json
  run: |
    cargo run --release
```

```toml
# 本地开发环境 (.translator)
[logging]
output = "file"
format = "pretty"
file = "logs/translator.log"
```

### 场景3：项目特定日志路径

**需求**: 不同项目的日志文件分离

**解决方案**: 在项目配置中指定相对路径

```toml
# 项目A/.translator
[logging]
file = "logs/project-a.log"
```

```toml
# 项目B/.translator
[logging]
file = "logs/project-b.log"
```
