# 代码库翻译工具分阶段实施方案

## 概述

本文档详细描述从现有 DeepLX 实现到完整代码库翻译工具的分阶段改造方案。每个阶段都有明确的目标、目录结构、调用链设计和验收标准。

---

## 第一阶段：基础架构搭建

### 目标

建立统一的分层架构基础，将现有 DeepLX 实现适配到新架构，实现最基本的翻译功能。

### 详细实现逻辑

#### 1. 错误类型定义（pkg/errors/errors.go）

定义整个项目使用的公共错误类型，包括配置错误、文件错误、翻译错误和缓存错误四大类。每个错误类型包含错误码、错误信息和是否可重试的标记。翻译错误还需要记录是哪个翻译提供商产生的错误。

#### 2. 领域实体定义（internal/domain/）

File 实体包含文件路径、内容、检测到的编码、文件哈希值和最后修改时间。TranslationUnit 实体表示一个可翻译的文本单元，包含唯一标识、类型（注释、文档字符串或错误信息）、原始内容、在文件中的起始和结束位置、检测到的语言以及是否需要翻译的标记。

#### 3. 配置模块（internal/config/）

配置结构体包含翻译设置（提供商、源语言、目标语言）、文件包含和排除规则、缓存设置和并发设置。配置加载器负责按优先级合并配置：命令行参数优先级最高，然后是环境变量，接着是指定的配置文件，最后是默认配置文件。如果找不到任何配置，使用内置默认值。

#### 4. 扫描器模块（internal/scanner/）

扫描器接口定义扫描方法，接收扫描选项参数，返回文件信息通道和错误通道。文件系统扫描实现递归遍历指定目录，根据包含和排除规则过滤文件，检测文件编码，计算文件哈希值。扫描过程使用并发处理以提高性能。

#### 5. 翻译器统一接口（internal/translator/interface.go）

定义 Translator 接口，包含单条翻译、获取翻译器名称和关闭方法。定义 BatchTranslator 接口继承 Translator，增加批量翻译和设置速率限制的方法。定义翻译请求和响应结构体，包含原文、译文、源语言、目标语言和备选翻译。

#### 6. 翻译器工厂（internal/translator/factory.go）

工厂维护一个从字符串到创建函数的映射表。提供注册方法允许注册新的翻译器类型。创建方法根据配置中的类型查找对应的创建函数并调用。初始版本只注册 DeepLX 一种类型。

#### 7. DeepLX 适配器（internal/translator/deeplx/translator.go）

适配器包装现有的 BatchTranslator 实现，将其适配到统一的 Translator 接口。单条翻译方法直接调用现有的带重试翻译方法，将结果转换为统一的响应格式。批量翻译方法复用现有的批量翻译逻辑。关闭方法为空实现，因为 DeepLX 翻译器不需要特殊清理。

#### 8. 应用入口（internal/app/app.go）

应用结构体包含配置、翻译器工厂、扫描器实例和日志记录器。初始化方法按顺序执行：加载配置、创建翻译器工厂、根据配置创建指定类型的翻译器、创建扫描器。运行方法接收目标目录参数，调用扫描器获取文件列表，对每个文件进行翻译处理。

#### 9. 主程序（cmd/translator/main.go）

解析命令行参数，包括目标目录路径、配置文件路径、源语言、目标语言、是否仅预览等选项。创建应用实例并初始化。调用应用的运行方法。处理程序退出信号，确保资源正确释放。

## 第二阶段：核心功能实现

### 目标

实现代码解析、缓存机制、文件写入等核心功能，形成完整的翻译流水线。

### 新增目录结构

```
translator/
├── internal/
│   ├── domain/
│   │   └── language.go             # Language 值对象定义

│   │   ├── go_parser.go            # Go 语言解析实现
│   │   └── registry.go             # 解析器注册表
│   ├── cache/
│   │   ├── cache.go                # Cache 接口定义
│   │   └── file_cache.go           # 文件缓存实现
│   ├── writer/

│   │   └── file_writer.go          # 文件写入实现
│   ├── encoding/

│   │   └── chardet.go              # chardet 库封装

│       └── reporter.go             # 翻译报告生成

### 详细实现逻辑

#### 1. 语言值对象（internal/domain/language.go）

定义 Language 结构体表示语言代码，提供验证方法确保语言代码符合标准。定义 FileType 结构体表示支持的编程语言类型，包含语言标识、文件扩展名列表和注释语法规则。

#### 2. 编码检测模块（internal/encoding/）

编码检测接口定义检测方法，接收文件路径或字节数组，返回检测到的编码格式和置信度。使用 chardet 库实现编码检测，支持 UTF-8、GBK、ISO-8859 等常见编码。提供编码转换方法，将文件内容从检测到的编码转换为 UTF-8 进行内部处理。

#### 3. 解析器模块（internal/parser/）

解析器接口定义解析方法，接收文件对象，返回翻译单元列表和支持判断方法。每个解析器实现需要识别该语言的单行注释、多行注释、文档注释和错误信息字符串的语法模式。

Go 语言解析器实现使用 Go 标准库的词法分析器，遍历文件的所有词法单元，识别注释标记。对于每个注释，提取其文本内容，检测是否包含目标语言的字符，如果是则创建翻译单元。同时识别 fmt.Errorf、errors.New 等错误信息构造函数的调用，提取其中的字符串参数。

解析器注册表维护文件扩展名到解析器的映射，根据文件扩展名查找对应的解析器。

#### 4. 缓存模块（internal/cache/）

缓存接口定义获取、设置、失效和清空方法。文件缓存实现在目标代码库目录下创建缓存目录，使用文件哈希作为键值存储翻译结果。缓存条目包含文件哈希、文件路径、最后修改时间和翻译单元列表。获取方法检查缓存文件是否存在且未过期，如果有效则返回缓存的翻译结果。设置方法将翻译结果序列化后写入缓存文件。

#### 5. 写入器模块（internal/writer/）

写入器接口定义写入方法，接收文件路径、原始编码、翻译单元列表和翻译结果。文件写入实现首先将翻译后的内容从 UTF-8 转换回原始编码，然后写入文件。保留原始文件的权限和时间戳。支持仅预览模式，在此模式下只输出将要修改的内容而不实际写入文件。

#### 6. 报告生成模块（internal/reporter/）

报告生成器收集翻译过程中的统计信息，包括处理的文件总数、跳过的文件数、翻译的单元数、API 调用次数和错误数。生成结构化的翻译报告，支持文本和 JSON 两种格式输出。

#### 7. 应用层协调（internal/app/app.go 扩展）

扩展应用结构体，增加解析器注册表、缓存实例、写入器实例和报告生成器实例。运行方法的工作流程：首先扫描目标目录获取文件列表，然后遍历每个文件执行以下步骤：检查缓存，如果文件未修改则跳过；读取文件内容并检测编码；调用对应的解析器提取翻译单元；过滤出需要翻译的单元；批量调用翻译器进行翻译；将翻译结果写回文件；更新缓存；记录统计信息。最后生成并输出翻译报告。

## 第三阶段：功能完善与优化

### 目标

### 详细实现逻辑

#### 1. 多语言解析器

Python 解析器实现需要识别以井号开头的单行注释、三引号包围的多行文档字符串。使用 Python 的词法规则进行解析，同时识别 raise Exception、logger.error 等错误信息构造。

JavaScript 和 TypeScript 解析器实现识别双斜杠单行注释、斜杠星号多行注释、双星号文档注释。需要处理 JSX 语法中的特殊注释形式，识别 throw new Error、console.error 等调用。

Java 解析器实现识别单行注释、多行注释、文档注释。使用 Java 的词法规则，识别 throw new Exception、logger.error 等调用。

#### 2. CLI 功能完善

命令行参数解析支持以下选项：目标目录位置参数、配置文件路径、源语言和目标语言覆盖、仅预览模式、详细日志模式、清空缓存、CI 模式、并发工作数、版本信息、帮助信息。

在 CI 模式下，程序行为发生变化：禁用所有交互式提示，使用 JSON 格式输出日志，遇到错误立即以非零退出码退出，不显示进度动画。

#### 3. 并发控制

使用工作池模式控制并发文件处理数量。创建指定数量的工作协程，每个工作协程从任务队列中获取文件进行处理。使用带缓冲的通道作为任务队列，避免内存无限增长。使用等待组同步所有工作协程的完成。在主协程中收集处理结果和错误。

#### 4. 缓存管理 CLI 命令

增加缓存管理子命令，支持清空缓存、查看缓存统计信息、验证缓存完整性。清空缓存命令删除缓存目录中的所有条目。查看统计命令显示缓存条目数量、总大小、命中率等信息。

#### 5. 初始化命令

实现初始化子命令，在指定目录生成示例配置文件。配置文件包含所有可配置项的注释说明和默认值，用户可以根据需要修改。

#### 6. 日志系统

实现分级日志系统，支持调试、信息、警告、错误四个级别。在详细模式下输出调试信息，包括每个处理步骤的详细状态。在 CI 模式下使用结构化日志格式，便于机器解析。

                    ├── 有错误且 CI 模式 ──▶ 非零退出码
                    │
                    └── 无错误或非 CI 模式 ──▶ 零退出码
```

### 验收标准

1. 支持 Python、JavaScript、TypeScript、Java 代码解析
2. CLI 支持所有规划的功能选项
3. CI 模式下程序行为符合预期
4. 并发处理正常工作，无数据竞争
5. 缓存管理命令正常工作
6. 初始化命令生成正确的示例配置
7. 日志分级输出正确

### 预留接口设计

#### LLM 翻译器接口

LLM 翻译器需要实现与 DeepLX 相同的 Translator 接口。额外需要支持系统提示词配置、温度参数设置、最大令牌数限制。提示词模板需要支持变量替换，包括源语言、目标语言和待翻译文本。

#### 插件接口

插件接口定义初始化、执行和清理三个生命周期方法。解析器插件可以注册新的语言解析器。翻译器插件可以注册新的翻译提供商。报告插件可以自定义报告输出格式。

## 实施建议

### 开发顺序

1. **第一阶段**：先实现 config、domain、errors 基础模块，然后实现 translator 接口和 DeepLX 适配器，最后完成 scanner 和 app 基础结构。

2. **第二阶段**：先实现 encoding 模块，然后实现 parser 接口和 Go 解析器，接着实现 cache 和 writer，最后完善 app 的协调逻辑。

3. **第三阶段**：先添加其他语言的解析器，然后完善 CLI 功能，最后实现并发控制和 CI 模式。

### 测试策略

每个阶段完成后进行集成测试，确保新增功能与已有功能协同工作。单元测试覆盖各模块的核心逻辑，特别是解析器和翻译器的边界情况。使用模拟翻译器进行测试，避免对外部 API 的依赖。

### 代码审查要点

- 接口定义是否清晰、完整
- 错误处理是否一致、完善
- 并发代码是否存在数据竞争
- 资源是否正确释放
- 日志输出是否有意义
