# 通用字符限制与限流功能设计文档

## 一、概述

本文档设计翻译器的通用字符限制、速率限制和长文本切分功能，确保翻译请求符合各API服务的要求。

---

## 二、现状分析

### 2.1 当前状况

**速率限制**
- 已实现基本的速率限制（使用令牌桶算法）
- 全局统一限流（默认10次/秒）
- 无法针对不同翻译器配置不同的速率限制

**字符限制**
- 完全缺失统一的字符限制机制
- 字符限制分散在各翻译器实现中
- DeepLX：无硬性检查
- LLM：依赖MaxTokens配置
- 腾讯云：计划支持

**长文本处理**
- 缺少超长文本自动处理机制
- 无法对超过限制的文本进行切分
- 切分后无法智能合并结果

### 2.2 各翻译器限制要求

| 翻译器 | 速率限制 | 字符限制 | 特殊要求 |
|--------|---------|---------|---------|
| DeepLX | 建议20次/秒 | 1500字符 | 需要切分 |
| LLM | 取决于服务商 | Token限制 | Token计数 |
| 腾讯云 | 5次/秒（硬限制） | 6000字符 | 需要切分 |

## 三、核心功能设计

### 3.1 字符限制

**设计目标**
- 在发送请求前验证文本长度
- 超出限制时返回明确错误
- 支持各翻译器配置不同的字符限制

**实现方式**
- 在翻译请求前检查文本字符数
- 与翻译器的字符限制配置对比
- 超出限制时返回错误信息，避免无效请求

**错误处理**
- 返回清晰的错误信息，说明当前限制和实际长度
- 错误不可重试，需要用户自行处理

### 3.2 速率限制

**设计目标**
- 防止超出API服务的速率限制
- 支持不同翻译器配置不同的速率
- 支持动态调整速率限制

**实现方式**
- 使用令牌桶算法进行速率控制
- 每个翻译器实例维护独立的限流器
- 速率参数：每秒请求数（Rate Limit）和突发数（Burst）

**限流策略**
- 请求时先检查令牌桶，有令牌则执行
- 无令牌则等待或返回错误
- 支持等待模式和快速失败模式

### 3.3 长文本切分

**设计目标**
- 自动检测超长文本
- 智能切分文本，保持语义完整性
- 支持多种切分策略
- 切分后合并翻译结果

**切分时机**
- 文本长度超过翻译器字符限制时自动触发
- 可配置是否启用自动切分

**切分策略**

**1. 字符切分（Char Split）**
- 按固定字符数切分
- 简单快速，但可能破坏语义
- 适用于：无格式要求的简单文本

**2. 句子切分（Sentence Split）**
- 按句子边界切分
- 保持语义完整性
- 切分点：句号、问号、感叹号等
- 适用于：叙述性文本、说明文档

**3. 段落切分（Paragraph Split）**
- 按段落边界切分
- 保持段落结构完整
- 切分点：空行、换行符
- 适用于：结构化文档

**4. 智能切分（Smart Split）**
- 综合使用多种策略
- 优先按段落切分
- 单段落过长时按句子切分
- 单句过长时按字符切分
- 适用于：通用场景

**切分参数**
- 最大字符数：单个分片的最大字符数
- 重叠字符数：相邻分片的重叠字符数（保持上下文）
- 是否保留标记：是否保留HTML、Markdown等标记

**切分流程**
1. 检测文本长度是否超过限制
2. 根据配置的策略选择切分方式
3. 按策略将文本切分为多个分片
4. 依次翻译每个分片
5. 合并翻译结果

**结果合并**
- 按原始顺序合并翻译结果
- 移除重叠部分（如果有）
- 保持原有格式和结构

## 六、配置结构

### 6.1 全局配置

**通用限制配置**
- rate_limit：每秒请求数
- burst：突发请求数
- max_char_count：单次最大字符数
- split_enabled：是否启用自动切分
- split_strategy：切分策略（char/sentence/paragraph/smart）
- split_max_chars：切分最大字符数
- split_overlap_chars：切分重叠字符数

**翻译器特定配置**
- 每个翻译器可以覆盖通用配置
- 如果未配置，使用通用配置或默认值

### 6.2 配置优先级

1. 翻译器特定配置
2. 通用限制配置
3. 默认配置

## 七、工作流程

### 7.1 翻译请求流程

1. 接收翻译请求
2. 检查字符限制
   - 如果超出限制且未启用切分，返回错误
   - 如果超出限制且启用切分，进入切分流程
3. 检查速率限制
   - 等待令牌或快速失败
4. 执行翻译
5. 记录统计信息
6. 返回翻译结果

### 7.2 切分翻译流程

1. 检测文本超出限制
2. 根据策略切分文本
3. 依次翻译每个分片
   - 每个分片都遵循正常翻译流程
4. 合并翻译结果
5. 记录切分统计
6. 返回合并结果

## 八、切分策略详细设计

### 8.1 句子切分逻辑

**识别句子边界**
- 句号（.、。）
- 问号（?、？）
- 感叹号（!、！）
- 换行符（\n）

**切分规则**
- 从句子边界处切分
- 保持句子完整
- 保留标点符号

**处理特殊情况**
- 缩写中的句号（如 Mr.、Dr.）不作为切分点
- 小数点不作为切分点
- 网址、邮箱中的点不作为切分点

### 8.2 段落切分逻辑

**识别段落边界**
- 连续的空行（\n\n）
- 文档中的标题标记（#、##等）

**切分规则**
- 从段落边界处切分
- 保持段落完整
- 保留段落格式

### 8.3 智能切分逻辑

**优先级顺序**
1. 按段落切分（最优先）
2. 单段落过长时按句子切分
3. 单句过长时按字符切分（最后选择）

**切分决策**
- 检测文本结构（是否包含段落）
- 检测句子边界
- 根据文本特征选择最佳策略

**保持上下文**
- 使用重叠字符数保持上下文
- 重叠部分通常包含前一个分片的末尾

### 8.4 字符切分逻辑

**切分规则**
- 按固定字符数切分
- 尽量在单词边界处切分
- 避免在单词中间切分

**优化切分点**
- 优先在空格处切分
- 其次在标点符号处切分
- 最后在任意字符处切分

## 附录

### A. 切分策略对比

| 策略 | 适用场景 | 优点 | 缺点 |
|-----|---------|------|------|
| 字符切分 | 简单文本 | 简单快速 | 可能破坏语义 |
| 句子切分 | 叙述性文本 | 保持语义完整 | 分割点不固定 |
| 段落切分 | 结构化文档 | 保持段落完整 | 可能过长 |
| 智能切分 | 通用场景 | 自动选择最佳策略 | 实现较复杂 |
